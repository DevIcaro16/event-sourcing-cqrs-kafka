# Phase 4 — Kubernetes com kind — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implantar toda a stack bancária (app Bun + Postgres write/read, Redis, Kafka) em um cluster Kubernetes local com kind, usando flat manifests YAML puros com todos os recursos de produção (StatefulSets, PVCs, NetworkPolicy, HPA, PDB, probes, MetalLB).

**Architecture:** Flat manifests em `k8s/` organizados por serviço. App Bun como Deployment com HPA e PDB. Bancos como StatefulSets com PVCs. MetalLB expõe a app via LoadBalancer IP. NetworkPolicy isola cada serviço. metrics-server habilita o HPA.

**Tech Stack:** kind v0.23+, kubectl, Docker, MetalLB v0.14.8, metrics-server v0.7.x, busybox:1.36

### Task 3: MetalLB + metrics-server + script de setup

**Files:**
- Create: `scripts/setup-metallb.sh`

- [ ] **Step 1: Criar diretório scripts e o script de setup**

```bash
mkdir -p scripts
```

```bash
# scripts/setup-metallb.sh
#!/bin/bash
set -e

echo "=== Instalando MetalLB v0.14.8 ==="
kubectl apply -f https://raw.githubusercontent.com/metallb/metallb/v0.14.8/config/manifests/metallb-native.yaml

echo "=== Aguardando MetalLB controller ficar pronto ==="
kubectl wait --namespace metallb-system \
  --for=condition=ready pod \
  --selector=app=metallb,component=controller \
  --timeout=90s

echo "=== Detectando subnet Docker do kind ==="
SUBNET=$(docker network inspect kind | python3 -c "import sys,json; nets=json.load(sys.stdin); print(next(c['Subnet'] for c in nets[0]['IPAM']['Config'] if ':' not in c['Subnet']))")
PREFIX=$(echo "$SUBNET" | cut -d. -f1-2)
POOL="${PREFIX}.255.200-${PREFIX}.255.250"
echo "Pool de IPs MetalLB: $POOL"

echo "=== Configurando IPAddressPool e L2Advertisement ==="
kubectl apply -f - <<EOF
apiVersion: metallb.io/v1beta1
kind: IPAddressPool
metadata:
  name: banking-pool
  namespace: metallb-system
spec:
  addresses:
  - ${POOL}
---
apiVersion: metallb.io/v1beta1
kind: L2Advertisement
metadata:
  name: banking-l2
  namespace: metallb-system
spec:
  ipAddressPools:
  - banking-pool
EOF

echo "=== Instalando metrics-server ==="
kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml

echo "=== Habilitando --kubelet-insecure-tls no metrics-server (necessário para kind) ==="
kubectl patch deployment metrics-server -n kube-system \
  --type='json' \
  -p='[{"op":"add","path":"/spec/template/spec/containers/0/args/-","value":"--kubelet-insecure-tls"}]'

echo "=== Aguardando metrics-server ficar pronto ==="
kubectl wait --namespace kube-system \
  --for=condition=ready pod \
  --selector=k8s-app=metrics-server \
  --timeout=90s

echo "=== Setup completo ==="
```

**Conceito chave:** Em k8s, o Kafka KRaft usa o headless service para discovery entre brokers. O `KAFKA_ADVERTISED_LISTENERS` deve ser o DNS do ClusterIP service (não `localhost`). O `KAFKA_CONTROLLER_QUORUM_VOTERS` usa o DNS do pod via headless service: `kafka-0.kafka-headless.banking.svc.cluster.local`.
